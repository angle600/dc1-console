# DC1 HTTP / UDP 接口手册（v1.1.0）

基地址：`http://<设备IP>`（默认端口 80）
所有 HTTP 响应均为 JSON（`/`、`/api/get` 除外），带 `Access-Control-Allow-Origin: *`。

## 0. 鉴权

两种等价写法，任选其一：

| 方式 | 示例 |
|---|---|
| 查询参数 | `?t=<你的 api_token>` |
| 请求头 | `X-Token: <你的 api_token>` |

- `config.api_token` 为空时（出厂默认），**所有接口均免鉴权**。
- 设置令牌后，下表标 ⚠️ 的接口返回 `401 {"err":"token"}`。

| 接口 | 需要令牌 |
|---|---|
| `/api/put`、`/api/get` | ⚠️ |
| `/api/config`（GET/POST） | ⚠️ |
| `/api/cal`（POST） | ⚠️ |
| `/api/reboot` | ⚠️ |
| 其余（state/switch/schedule/countdown/time/log/keys/energy/meter/ping/info） | 否 |

> 设计取舍：**开关类接口故意不加鉴权**，让网页/手机免配令牌即可用；
> 凡能改固件或读文件的接口一律要求令牌。

## 1. 只读接口

### `GET /api/ping`
最轻量存活探测。

```json
{"ok":1,"type":"DC1","fw":"1.1.0"}
```

### `GET /api/info`
设备身份（UDP 发现返回同一结构）。

```json
{"t":"dev","proto":1,"type":"DC1","id":"dc1-0400","name":"客厅排插",
 "fw":"1.1.0","mac":"dc:4f:22:04:9c:ef","ip":"192.168.31.243",
 "port":80,"prov":0,
 "features":["switch","schedule","countdown","meter","energy","ota-py","prov-udp"]}
```

### `GET /api/state`
全量状态，网页每 3 s 轮询一次。

```json
{"time":1794978257,"ip":"192.168.31.243","rssi":-56,
 "total":true,"1":true,"2":false,"3":false,"logo":true,
 "meter":{"voltage":221.8,"current":0.451,"power":98.6,
          "uk":123456,"ut":54321,"ik":2345,"it":4321,
          "pk":34567,"pt":12345,"energy_pulses":12,
          "calibrated":1,"flags":0},
 "energy":{"total_kwh":1.2345,"today_kwh":0.0123},
 "sched":2,"cd":[],
 "fw":"1.1.0","type":"DC1","ap":0,"prov":0}
```

| 字段 | 含义 |
|---|---|
| `total` / `1` / `2` / `3` | 总闸 / 三路插孔开关状态 |
| `logo` | 面板指示灯 |
| `meter.calibrated` | 1 = 芯片帧头 0x55（出厂标定有效） |
| `meter.flags` | bit3/2/1 超量程，bit0 系数区异常 |
| `ap` | 1 = 当前在 AP 配网模式 |
| `prov` | 1 = 上电 30 s 内的 UDP 配网窗口开着 |

### `GET /api/energy`
```json
{"total_kwh":1.2345,"today_kwh":0.0123}
```
`today_kwh` 按设备本地日期（DOY 变化）自动清零。

### `GET /api/meter`
只返回计量字段（同 `state.meter`），适合高频轮询。

### `GET /api/keys`（已移除）
按键调试：U7 原始输入寄存器 + GPIO16 电平。

```json
{"u7":true,"raw":15,"total_pin":1}
```
> 空闲基线在启动时采集并写入 `boot.log`；按下时 `raw` 与基线不同即为触发。

### `GET /api/log`
启动日志（每次启动重写）。

```json
{"log":"wifi: STA\nhttp bind: ok\nkeys idle: {'1': 1, '2': 1, '3': 1} total=1\nhw: uart=True i2c=True\nmeter: True\nfree: 5040\n"}
```

### `GET /api/cal`
标定信息与原始量。

```json
{"meter":{"v_gain":1.0,"i_gain":1.0,"p_gain":1.0,"v1r":1.0,"v2r":1.0},
 "measured":{"voltage":221.8,"current":0.451,"power":98.6},
 "raw":{"uk":123456,"ut":54321,"ik":2345,"it":4321,"pk":34567,"pt":12345},
 "calibrated":1,"flags":0}
```

## 2. 控制接口

### `GET|POST /api/switch?ch=<通道>&on=<0|1>`
通道：`total` / `1` / `2` / `3` / `logo`。返回完整 `state`。

```bash
curl "http://<ip>/api/switch?ch=1&on=1"
```
> 总闸 OFF 会级联关闭三路；打开任一分路会自动合上总闸。

### `GET /api/schedule` / `POST /api/schedule`
规则结构：`{"id","ch","on","hh","mm","days","en"}`

- `days`：**位掩码**，bit0=周一 … bit6=周日（`127`=每天）；**`days=0` 表示单次**，触发后自动删除。

```bash
# 列表
curl "http://<ip>/api/schedule"

# 新增（工作日 07:30 开 1 路）
curl -X POST "http://<ip>/api/schedule" \
     -d '{"op":"add","ch":"1","on":1,"hh":7,"mm":30,"days":31,"en":1}'

# 删除 / 启用停用 / 清空
curl -X POST "http://<ip>/api/schedule" -d '{"op":"del","id":1}'
curl -X POST "http://<ip>/api/schedule" -d '{"op":"en","id":1,"en":0}'
curl -X POST "http://<ip>/api/schedule" -d '{"op":"clear"}'
```

### `GET /api/countdown` / `POST /api/countdown`
```bash
curl -X POST "http://<ip>/api/countdown" -d '{"op":"add","ch":"2","on":1,"sec":600}'
curl -X POST "http://<ip>/api/countdown" -d '{"op":"del","id":1}'
curl -X POST "http://<ip>/api/countdown" -d '{"op":"clear"}'
```
列表返回 `[{"id":1,"ch":"2","on":1,"left":598.3}]`（`left` 单位秒）。

### `POST /api/time`
写 RTC（用于无外网时手动校时）。

```bash
curl -X POST "http://<ip>/api/time" -d '{"epoch":1794978257}'
```
设备内部按 `epoch + 8h` 写入本地时间。

### `POST /api/cal` ⚠️
单点标定 / 恢复默认。**默认不需要标定**（芯片出厂系数已随帧下发）。

```bash
# 给真实电压，反算 v_gain
curl -X POST "http://<ip>/api/cal?t=<token>" -d '{"voltage":221.8}'
# 给真实功率
curl -X POST "http://<ip>/api/cal?t=<token>" -d '{"power":98.6}'
# 直接写硬件常量
curl -X POST "http://<ip>/api/cal?t=<token>" -d '{"v1r":1.0,"v2r":1.0}'
# 恢复默认
curl -X POST "http://<ip>/api/cal?t=<token>" -d '{"reset":1}'
```

### `GET|POST /api/config` ⚠️
读（不含 `password`）/ 写配置。

```bash
curl "http://<ip>/api/config?t=<token>"
curl -X POST "http://<ip>/api/config?t=<token>" -d '{"name":"客厅排插"}'
# 改 WiFi 并立即重启
curl -X POST "http://<ip>/api/config?t=<token>" \
     -d '{"ssid":"<你的SSID>","password":"<你的WiFi密码>","reboot":1}'
# 清空凭据 → 重启进 AP 配网
curl -X POST "http://<ip>/api/config?t=<token>" -d '{"wifi_reset":1}'
```

可写键：`ssid` `password` `name` `ap_ssid` `ap_pass` `api_token` `http_port`
`hostname` `meter_enabled` `hw` `meter`（对象）。其他键会被忽略。

### `POST /api/reboot` ⚠️
```bash
curl -X POST "http://<ip>/api/reboot?t=<token>"
```

## 3. 文件接口（OTA）

### `POST /api/put` ⚠️
分片写文件，用于无线更新 `app.mpy` / `index.html`。

```json
{"name":"app.mpy","off":0,"b64":"<base64 分片>"}
```
返回 `{"ok":1,"name":"app.mpy","off":<下一偏移>}`。

- 分片建议 **256 B**（1 MB 版堆只有 ~5 KB，512 B 会 `MemoryError`）。
- 首片会自动释放计量对象（`free_meter()`）腾内存，重启后恢复。
- `off=0` 时以 `wb` 打开（截断旧文件）。

客户端：`python tools/tcp_push.py --ip <ip> --token <token> --file app.mpy --name app.mpy`

### `GET /api/get?name=<文件>&off=<偏移>&len=<长度>` ⚠️
读文件分片，返回 base64（**每行带 `\n`**，解码前先 `split()`）。

```bash
curl "http://<ip>/api/get?name=app.mpy&off=0&len=192&t=<token>"
```
> 单次读取上限受堆限制，建议 `len<=192`。

### `POST /api/file?name=<文件>` ⚠️
整文件直写，仅允许 `.py` / `.json`，body 为原始内容（非 base64）。

```bash
curl -X POST "http://<ip>/api/file?name=config.json&t=<token>" --data-binary @config.json
```

## 4. UDP 54321 协议

单包 JSON，明文，无鉴权（仅局域网）。设备回包同样是 JSON。

| `t` | 请求 | 响应 |
|---|---|---|
| `discover` / `who` | `{"t":"discover"}` | `info_obj()`（同 `/api/info`） |
| `prov` | `{"t":"prov","ssid":"X","pass":"Y","name":"客厅"}` | `{"t":"prov","ok":1}`；窗口关闭时 `{"ok":0,"err":"window_closed"}` |
| `log` | `{"t":"log"}` | `{"boot":"...","err":"..."}` |
| `put` | `{"t":"put","name":"app.mpy","off":0,"b64":"..."}` | `{"ok":1,"off":<下一偏移>}` |

- `prov` 只在**上电后 30 秒**内有效（`state.prov=1`）。
- 广播可能被路由器拦截（有线→无线），发现失败时改用 `/24` 单播扫描（`cli discover` 已内置）。

## 5. 错误约定

| HTTP | body | 含义 |
|---|---|---|
| 400 | `{"err":"bad ch"}` / `{"err":"bad op"}` / `{"err":"bad epoch"}` | 参数不合法 |
| 401 | `{"err":"token"}` | 需要令牌或令牌错误 |
| 404 | `{"err":"..."}` | 路由不存在 / 文件不存在 / **MemoryError** |
| 503 | `{"err":"meter_off"}` | 计量未初始化（`meter_enabled=false` 或安全模式） |

> 注意：`/api/get` 在堆不足时也返回 **404 + MemoryError**，不是“文件不存在”。

---

## 6. 已知限制

- `switch`/`schedule`/`countdown`/`time` 无鉴权，同网段任何人都能操作。
- 单线程服务：一次只处理一个请求，并发 >4 会排队（listen backlog 4）。
- `meter_enabled` 与 OTA 冲突：OTA 会临时释放计量对象。
- 设备重启约需 10–15 s 才重新可访问。

## 7. v1.2 精简版变更（2026-11-18）

为把 1 MB ESP8266 的空闲堆从 4.1 KB 提到 **5.5–6 KB**，删除了以下接口：

| 已移除 | 原因 |
|---|---|
| `GET /api/cal`、`POST /api/cal` | 计量默认用芯片出厂标定，不需要现场标定 |
| `POST /api/file` | 与 `/api/put` 重复，且整文件写入在低内存下必失败 |
| `GET /api/keys` | 调试用，按键已改为基线比对 |
| `GET /api/sys` | 调试用 |

同时做了三处运行时优化：

1. `state_json()` 直接拼字符串（省掉 dict + `json.dumps` 两轮大分配）；
2. 路由分发前 `gc.collect()`，缓解堆碎片；
3. **OTA 改为设备端 sha256 校验后提交**：
   `POST /api/put {"name","done":1,"sha":"<hex>"}` → 设备算 `sha256(tmp)` 比对，
   一致才 `rename`；不一致返回 `{"err":"sha mismatch"}`，旧固件不受影响。

> 提交请求**不再携带 `off`**。历史上一次 `done` 带 `off=0` 把 `app.mpy` 截成 0 字节，
> 导致启动失败 —— 现在 `done` 分支只做校验与改名，绝不写内容。
