# DC1 装配与标定手册（MicroPython 固件）

> 适用：斐讯 DC1 排插（ESP8266 + CAT9554 + CSE7766），固件 v1.1.0
> 前置：板子已刷 MicroPython 1MB 版 + 本仓库 `firmware/micropython/` 全部文件

---

## 1. 装配前检查清单

按顺序逐项确认，任一项不过先别装壳。

| # | 检查项 | 方法 | 通过标准 |
|---|---|---|---|
| 1 | WiFi 联网 | `curl http://<ip>/api/ping` | `{"ok":1,...}` |
| 2 | 网页可用 | 浏览器打开 `http://<ip>/` | 开关/定时/电量三块都在 |
| 3 | 总闸 | 网页点「总开关」 | 继电器"嗒"一声，状态变 ON |
| 4 | 分路 1/2/3 | 逐个点击 | 各自继电器动作，互不干扰 |
| 5 | 总闸联锁 | 分路 ON 时点总闸 OFF | 分路状态一起变 OFF |
| 6 | 断电记忆 | 置 total+1 ON → `POST /api/reboot` | 重启后状态保持 |
| 7 | 倒计时 | 网页设 1 分钟 | 到点自动动作 |
| 8 | 按键 | 见 §2 | `raw` / `total` 有跳变 |
| 9 | OTA | `tools/tcp_push.py` 推 `app.mpy` | 回读 sha256 一致 |
| 10 | 开放热点关闭 | 手机搜 WiFi | **搜不到** `MicroPython-xxxxxx` |

## 2. 按键验证（唯一需要人手的项）

终端持续读原始电平：

```bash
while true; do curl -s http://<ip>/api/keys; echo; sleep 0.3; done
```

按住某键 2 秒，观察变化：

| 现象 | 结论 | 处理 |
|---|---|---|
| `raw` 由 15 变 14/13/11/7 | 该键正常 | 记录对应键位 |
| `raw` 恒 15 | 键电路未接到 U7 / 排线断 | 查按键排线与 U7 P0-P2 |
| `total_pin` 由 1 变 0 | 总键正常（低有效） | — |
| `total_pin` 恒 1 | 总键未接地或需外部下拉 | 查 GPIO16 到按键的走线 |

固件用「上电基线比对」，**不假设高/低有效**，所以只要能读到跳变就算通过。

## 3. 装回排插

1. **断电**，拔掉 TTL 的 `3V3`（只留 `GND`，或全部拔掉）；
   > 板子装回后由自身电源供电，TTL 的 3V3 与板上 3V3 并联会顶牛。
2. 板子固定、插头/按键排线复位，合壳；
3. 排插插入 220 V 墙壁插座（此时 ESP 由板载电源供电）；
4. 等 10 s，确认 WiFi 上出现设备（`cli discover` 或路由器列表）；
5. 打开网页，读电压 ≈ 220 V。

> 若 10 s 内没上线：设备可能进了 AP 模式（`DC1-Setup` / `dc1setup`），
> 手机连上后打开 `http://192.168.4.1` 重新填 WiFi。

## 4. 计量：默认不标定

**原厂已经把标定写进 CSE7766 芯片内部**（独立的 EEPROM/OTP），与我们重写 ESP8266 的
Flash **完全无关**；固件驱动只接收、从不向芯片写校准命令，因此这份数据不会丢。

所以装壳通电后：

1. 先直接读 `/api/cal`，看 `measured.voltage` 是否 ≈ 220 V、接负载后 `power` 是否吻合；
2. **读数准确就保持 `v_gain=i_gain=p_gain=1.0`，不要标定**；
3. 只有出现**系统性偏差**（例如恒定读成 198 V 或 1.08 倍）时，才做一次单点补偿（§4.2）。

> 判断依据：`calibrated` 字段为 1 表示芯片帧头 0x55（已校准）。若为 0，说明这颗芯片
> 的出厂标定确实丢了（或从未烧），才需要走完整标定流程。

### 4.1 先看原始读数

```bash
curl -s "http://<ip>/api/cal?t=<token>"
```

返回 `meter`（当前增益）、`measured`（换算后的 V/A/W）、`raw`（uk/ut/ik/it/pk/pt）、
`calibrated`（芯片标定标志）、`flags`（超量程/系数异常位）。

### 4.2 仅在确有必要时做单点补偿

给出一个真实值，固件反算增益并存盘（等价于反解板级 `V1R`/`V2R`，但不动芯片）：

```bash
# ① 电压：万用表读插座实际值，例如 221.8 V
curl -X POST "http://<ip>/api/cal?t=<token>" -d '{"voltage":221.8}'

# ② 功率：接已知负载（如 100 W 白炽灯），填负载实际功率
curl -X POST "http://<ip>/api/cal?t=<token>" -d '{"power":98.6}'

# ③ 电流（可选，有钳表再做）
curl -X POST "http://<ip>/api/cal?t=<token>" -d '{"current":0.45}'
```

内部即 `v_gain = 真实值 × ut / uk`（电流/功率同理），结果写入 `config.json`，重启不丢。

**恢复默认**（回到“完全信任芯片标定”）：

```bash
curl -X POST "http://<ip>/api/cal?t=<token>" -d '{"reset":1}'
```

### 4.3 电量核对

连续运行 1 小时已知功率负载，比对 `today_kwh` 与「功率 × 时间」：

- 误差 <3% 可接受；
- 偏差成比例 → 调 `p_gain`；
- 偏差与功率无关（固定偏移）→ 检查 `pt` 本底。

## 5. 日常运维

```bash
# 发现设备（广播被路由器挡时会自动扫 /24）
python cli/dc1ctl.py discover

# 读状态
python cli/dc1ctl.py --ip <ip> state

# 开关
python cli/dc1ctl.py --ip <ip> on 1
python cli/dc1ctl.py --ip <ip> off total

# 无线更新固件（带完整性校验）
python tools/tcp_push.py --ip <ip> --token <token> \
       --file firmware/build/mpy/app.mpy --name app.mpy

# 远程重启
python tools/tcp_push.py --ip <ip> --token <token> --reset

# 读启动/错误日志
curl -s "http://<ip>/api/log"
curl -s "http://<ip>/api/get?name=err.log" | base64 -d
```

## 6. 故障恢复

| 症状 | 判断 | 处理 |
|---|---|---|
| 网页打不开、UDP 也没回应 | 程序卡死 | 断电重上电（看门狗 8 s 会自愈，但完全死锁需断电） |
| 上电后串口停在 `SAFE BOOT` | 上次启动崩溃 | REPL 里 `print(open('err.txt').read())` 看原因 |
| 改了 `app.mpy` 后无限重启 | 新固件自身崩溃 | 串口进 REPL，`os.remove('app.mpy')` 后重传 |
| 需要彻底重刷 | FS 损坏/忘记密码 | `IO0` 接 GND 上电 → `esptool write-flash -e` → 重传文件 |
| 要回原厂 | 放弃自定义固件 | `firmware/` 里的原厂 dump 按 `docs/01-刷机方案.md` 写回 |


### 6.1 OTA 自愈演练（2026-11-18 实测通过）

故意把 `app.mpy` 写成 56 B 垃圾数据，模拟"升级包损坏/断电传输不完整"：

```
① POST /api/put 写入 56 B 坏包（回读校验通过，说明是内容坏而非传输坏）
② POST /api/reboot
③ 串口输出：
     rst cause:1
     SAFE BOOT: app 已跳过（上次启动失败），REPL 可用
     >>> 
   err.txt 记录：ValueError: incompatible .mpy file  (main.py line 18)
   HTTP 停止服务（curl 502），WiFi 仍连着
④ 串口回传正确 app.mpy（16,336 B）→ 复位
⑤ /api/sys 恢复：{"up":1.7,"reset":4,"free":2880}
```

**结论**：坏包不会把设备变砖 —— 加载器直接拒绝 → `safe.flag` 触发安全启动 →
REPL 在 GPIO1/3 上可用（此时固件未 import app，UART 未被 swap）→ 串口回传即可恢复。

关键前提（已验证）：

- `main.py` 用 `try: import app` 包住，异常时写 `err.txt` + `safe.flag` 再 `machine.reset()`；
- 安全启动时**不 import app**，因此 UART 保持在默认 GPIO1/3，串口能进；
- `safe.flag` 被消费后自动删除，下次正常启动不受影响。

> 若连 REPL 也进不去（例如刷坏了内核本身），最后一招是 `IO0→GND` 重新 `write-flash -e`。

### 刷写命令（备忘）

```bash
# 进下载模式：IO0→GND，断电再上电
python -m esptool --port COM8 --baud 460800 --before no-reset --after no-reset \
       write-flash -e --flash-size 1MB 0x0 firmware/micropython-1m-v1.29.0.bin

# 拆 IO0，重新上电后上传文件
python -m mpremote connect COM8 cp main.py app.mpy store.mpy cat9554.mpy \
       cse7766.mpy index.html config.json :
```

> 刷写会清空文件系统，`config.json` 需要重新上传（或在 AP 模式网页重配）。

## 7. 已知限制

- **RAM 极紧**：1 MB 版堆约 5 KB 空闲，OTA 前必须 `free_meter()`；分片 256 B 才稳。
- **计量与 OTA 互斥**：OTA 会释放计量对象，重启后自动恢复。
- **广播不可达**：部分路由器拦截有线→无线广播，发现改走 /24 单播扫描（约 4 s）。
- **`/api/switch` 无鉴权**：局域网内可直接开关；写文件类接口（put/file/config）需要 token。
