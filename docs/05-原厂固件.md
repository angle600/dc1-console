# 05 · 原厂固件：能不能读、读到什么、怎么用

## 1. 结论

**能读出来，而且是完整 1MB**（ESP8266 无读保护），三条途径：

| 途径 | 需要 | 拿到什么 | 适用 |
|---|---|---|---|
| **① 自己 dump（唯一权威）** | 拆机 + TTL + IO0 接地 | 你这台机器的完整镜像（含 NVRAM/配置区） | 刷机前必做 |
| **② 社区已 dump 的镜像** | 无需拆机 | 同批次通用镜像（本次已下载校验） | 只想研究/对比 |
| **③ 串口日志** | 只接 LOG_TX | 启动日志、任务名、型号 | 不改固件时观察行为 |

```bash
# ① 自己的机器（IO0→GND 进下载模式）
esptool.py --port COM5 flash_id                      # 确认 1MB
esptool.py --port COM5 --baud 460800 read_flash 0 0x100000 backup/dc1_original_1M.bin
esptool.py --port COM5 verify_flash 0 backup/dc1_original_1M.bin
```

> ⚠ 刷写我们的固件会**覆盖**原厂镜像；没有 dump 就无法回到原厂。链路里一旦擦除，社区镜像只能救"型号通用"部分，救不回你机器独有的配置区。

## 2.1 实操：一条 `read-flash` 为什么会断，怎么读才稳

本次实机（DC1，ESP8266EX，1MB，USB-TTL 3.3V 供电）实测：

| 方式 | 结果 |
|---|---|
| `read-flash 0 0x100000` @460800 + stub | 176 KB 处 `Read more than expected` |
| `read-flash 0 0x100000` @115200 `--no-stub` | 740 KB 处 `No more data to read` |
| 64 KB 分块，每块独立进程 | 11 块（704 KB）后断在 `0x0B0000` |
| **8 KB 分块 + 每块独立进程 + 0.2 s 间隔 + 2 次重试** | **49 块全过，392 KB 零失败** |

结论：这类供电/链路下，**短会话**才稳；单次长读约 60–70 s 就会掉。
脚本已提供：

```bash
python tools/dump_flash.py --port COM8 --size 1MB --chunk 0x2000 --baud 115200 \
    --out backup/dc1_original_1M.bin
# 断线后重跑同一命令即可续读（已读块跳过）
python tools/join_dump.py --dir backup/dc1_original_1M.bin.chunks --size 1MB \
    --out backup/dc1_original_1M.bin --compare firmware/original/dc1_original_1M.bin
```

## 2.2 本次读出的这台机器（存档信息）

```
MAC          : dc:4f:22:04:9c:ef   （镜像内位置 0x0FD484，system param 区）
镜像版本串   : PHI_CS-EHS707_V0.2.34A_240 / PHI_CS-EHS707_V0.2.39B_324
size / sha256: 1,048,576 B / a547ffd1c890713ca2264533d78eab6a41f7c970a1d11c8ab9eaa22e45302610
校验         : 4 点抽样回读逐字节一致（0x0 / 0x1E000 / 0x54000 / 0xF0000）
```

与社区镜像（`PHI_CS-EHS707_V0.2.39A_324`，sha256 `107f59bd…`）对比：

- **app 区（0x1000–0x54000）差异 96.3%** —— 不是同一版固件，社区那份不能当"同款备份"；
- `0x60000–0x7FFFF`、`0xE0000` 两边都是 100% `0xFF`（空白，故显示"相同"）；
- `0xF0000` 段差 623 B —— 就是 MAC / RF 校准 / NVS 这类逐台不同的数据。

> 所以：**自己的 dump 不可替代**，社区镜像只能救"能开机"这一层。

## 3. 从 dump 里能挖到什么、挖不到什么

| 目标 | 可行性 | 说明 |
|---|---|---|
| 型号/版本/产品码 | ✅ | `strings` 直接读（见上） |
| 继电器/按键/计量任务结构 | ✅ | 函数名与错误串可见 |
| 是否用 CSE7766 出厂系数 | ✅ 间接 | 有 `cse7766-check` 分支，说明会校验帧头/系数 |
| **V1R / V2R 具体数值** | ⚠ 需反汇编 | 编译进代码的常量；需 `xtensa-lx106-elf-objdump`（本机无）。浮点常量扫描会被代码字节干扰，不足为凭 |
| 原厂 WiFi 配网协议 | ⚠ 需抓包 | 建议直接抓 UART/无线包，比逆代码快 |

所以"按原厂数据计量"的现实路线仍是 **一次比对反求 V1R/V2R**（见 README「用回原厂标定」）：
芯片里的 `Uk/Ik/Pk` 是出厂标定，我们照用；只补板级两个常量。

## 4. 工具：`tools/fw_scan.py`

```bash
python tools/fw_scan.py firmware/original/dc1_original_1M.bin --unit-scan
```

输出：镜像头（魔数/段数/flash 大小/入口）、`sha256`、关键字命中的字符串、32 位浮点常量直方图、
以及 0.5~4.0 区间的常量偏移（用于人工判读——**仅供参考，不能当结论**）。

## 5. 安全与合规

- dump 仅用于**本机备份与互操作研究**；不要分发厂商固件（社区镜像版权属原厂）。
- 社区镜像（`dc1_original_1M.bin`）**不提交**；主人本机的逐字节备份
  `firmware/original/dc1_original_1M_user.bin` 已入库，仅作**个人设备还原点**存档
  （版权仍属原厂，勿商业分发；给他人刷机请让对方 dump 自己的机器）。
- 强电操作：断电、放电、单人作业；烧写前先确认 3.3V 与 GND 没有接反。
