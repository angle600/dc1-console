# 01 · 刷机方案（DC1 → ESPHome 自用固件）

## 0. 结论先行

| 项 | 选择 | 理由 |
|---|---|---|
| 固件底座 | **ESPHome（ESP8266）** | 原厂模组 CSM64F02 ≙ ESP-WROOM-02，可直接刷；自带 AP 配网、OTA、Native API、Web |
| 驱动 | 仓库自带 `components/cat9554`（或原生 `pca9554`） | U7 是简配 CAT9554，官方组件默认 50kHz+ 会通信失败 |
| 配网 | ESPHome `captive_portal` 强制门户 | 手机连热点自动弹页，无需装 App、无需安卓 |
| AI 控制 | Native API 6053 + `tools/dc1ctl.py` | 状态可回读、走局域网、无云依赖 |
| 刷写方式 | TTL 线刷一次 → 之后全 OTA | 只需焊/夹一次，后续升级不用再拆 |
| 备份 | 刷前整体 dump 1MB/2MB 原厂固件 | 唯一后悔药，务必做 |

**全程只有一次拆机**：线刷成功后所有改动都走 OTA（80/6053/3232 内网）。

## 1. 物料与工具

| 物料 | 规格 | 说明 |
|---|---|---|
| USB-TTL | **3.3V 电平**，CH340/CP2102 均可 | 5V TTL 会打坏模组 |
| 焊接 | 尖头烙铁 + 0.6mm 焊锡 + 助焊剂，或 SOIC-8 测试夹/探针 | 焊盘极小且脆，见风险表 |
| 杜邦线 | 母-母 4 根 | TX/RX/GND/3.3V |
| 螺丝刀 | PH0/PH1 十字 + 撬棒 | 外壳卡扣 + 隐藏螺丝 |
| 万用表 | — | 确认 3.3V/5V 与继电器动作 |
| 可选 | ESP-Prog、逻辑分析仪 | 排障用 |

软件：Python 3.10+、`pip install esphome esptool`；或 Docker `esphome/esphome`。

## 2. 拆机与安全（必读）

> **220V 强电 + 非隔离电源**：板上任何一点都可能是火线电位。**拔插头、等 30 秒放电、不再插电**才动烙铁。

1. 拔电源，拆底部 4 颗螺丝（其中 1 颗在防拆贴下）。
2. 沿卡扣撬后盖；**先拔 P1 小排线（主控板↔电源板）**——社区多人拽断，焊盘脱落即报废。
3. 取出主控板（黑色小板），拍照留档（走线、排线方向）。
4. 主控板单独用 **3.3V** 供电（模组 3.3V 脚 + GND），不要用排插自身 5V 反复上电调试。

**已知坑**：`主控制板`上 `RX1`、`IO0`、`LOG_TX` 三个测试点最结实，优先焊这三点 + `GND`；
模组两侧引脚间距 1.27mm，焊锡易连桥。

## 3. 备份原厂固件（刷机前第一件事）

模组 Flash 1MB（部分批次 2MB，**先探测**）：

```bash
# 1) 进入下载模式：GPIO0(测试点 IO0) 短接到 GND，再给 3.3V 上电/复位
esptool.py --port COM5 flash_id
# 期望看到 Detected flash size: 1MB（若是 2MB，下面长度改 0x200000）

# 2) 整体 dump
esptool.py --port COM5 --baud 460800 read_flash 0 0x100000 backup/dc1_original_1M.bin

# 3) 校验（两次 dump 比对 md5，必须一致）
esptool.py --port COM5 verify_flash 0 backup/dc1_original_1M.bin
```

- 备份文件另存**两处**（本机 + 网盘），并记下 md5。
- 参考：原厂固件已有人上传到上游仓库（`bin/dc1_original_1M.bin` / `2M.bin`），可作交叉验证，
  但**自己的 dump 才是你这台机器的唯一还原点**。

## 4. 编译固件

```bash
cd firmware
cp secrets.example.yaml secrets.yaml    # 然后填 wifi/api/web/ota 密码
pip install -U esphome
esphome config dc1-ai.yaml              # 先校验 YAML 语法
esphome compile dc1-ai.yaml
```

产物：`firmware/build/dc1-plug/.pioenvs/dc1-plug/firmware.bin`（含 bootloader，整片烧 0x0）。

关键点：
- `components/` 必须与 `dc1-ai.yaml` **同级**，ESPHome 才加载本地 `cat9554` 组件。
- `i2c.frequency: 20kHz` 不能删；改成 50k/100k 会出现继电器乱跳或 U7 无响应。
- `logger.baud_rate: 0` 不能删；UART0 被 swap 给 CSE7766 用（GPIO13/15），开日志会抢总线。
- `esp8266_restore_from_flash: true` + `restore_mode: RESTORE_DEFAULT_OFF` 保证断电记忆正常。

### 若自定义组件编译不过（新版 ESPHome API 变动）

改用原生组件，二选一：

```yaml
# 删掉 cat9554: 段，加：
pca9554:
  - id: cat9554_hub
    address: 0x20
    irq_pin: GPIO4
```
并把所有 `cat9554: cat9554_hub` 改成 `pca9554: cat9554_hub`。
（寄存器完全兼容 CAT9554；若仍不稳，把 `i2c.frequency` 降到 `10kHz`。）

## 5. 线刷 / 读固件（唯一需要焊线的一次）

**读固件和烧固件用的是同一组线**，只有 esptool 的命令不同。

### 5.1 接线（USB-TTL 3.3V ↔ 主控板测试点）

| TTL 侧 | 主控板测试点 | 丝印/位置 | 说明 |
|---|---|---|---|
| **3V3** | `3.3V` | 正面左侧第 2 个测试点 | 只给模组供电，**严禁接 5V** |
| **GND** | `GND` | 正面左侧第 1 个 | 必须共地，否则同步失败 |
| **RX** | `LOG_TX` | 正面左侧，GPIO1 | 交叉：TTL 收 ← 板 发 |
| **TX** | `RX1` | 正面左侧，GPIO3 | 交叉：TTL 发 → 板 收 |
| —（短接） | `IO0` → `GND` | 正面左侧 IO0 测试点 | **下载模式**，刷完必须断开 |

板上还有 `ADTEST`、`RELAY` 两个测试点，刷机**不用**碰。

> 注意：`RX1` 在运行期被我们的固件借去当 I2C SDA（CSE7766 又把 UART0 swap 到 GPIO13/15），
> 但 ROM 下载模式在固件启动之前，所以**刷写不受影响**；只是刷完后 USB 口看不到业务日志。

### 5.2 进入下载模式（DC1 没有引出 DTR/RTS，只能手动）

1. 断电（拔掉 3.3V 与市电），`IO0` 用镊子/杜邦线**短接到 GND** 并保持；
2. 给 3.3V 上电（此时模组以下载模式启动，串口会吐 `ets Jan  8 2013,rst cause:2...boot mode:(1,...)`）；
3. 保持 IO0 短接，执行 esptool（加 `--before no_reset`，别让它去拨 DTR/RTS）：

```bash
# 连接自检
esptool.py --port COM5 --before no_reset --after no_reset flash_id
# 期望：Chip is ESP8266EX / Detected flash size: 1MB
```

### 5.3 读（备份，刷机前第一件事）

```bash
esptool.py --port COM5 --baud 460800 --before no_reset --after no_reset \
    read_flash 0 0x100000 backup/dc1_original_1M.bin
esptool.py --port COM5 --before no_reset --after no_reset \
    verify_flash 0 backup/dc1_original_1M.bin
```

### 5.4 写（ESPHome / MicroPython 内核 / 回滚原厂）

```bash
# 整片镜像一律写 0x0
esptool.py --port COM5 --baud 460800 --before no_reset --after no_reset \
    write_flash --flash_mode dout 0x0 firmware.bin

# 回滚原厂
esptool.py --port COM5 --baud 460800 --before no_reset --after no_reset \
    write_flash 0x0 backup/dc1_original_1M.bin
```

ESPHome 路线也可以用 `esphome run dc1-ai.yaml --device COM5`（它自己调 esptool）。

### 5.5 收尾

1. **先断开 IO0-GND**，再断电、重新上电；
2. 74880/115200 应看到启动信息（原厂 115200；MicroPython 115200，但被 CSE7766 swap 后会搬到 GPIO13/15，
   按住总键上电可保留 REPL）；
   - **调试模式（`debug_log_tx=true`，仓库默认）**：UART0 不 swap，LOG_TX(GPIO1) 115200 直出启动日志，
     无需按住任何键。已验证 `=== DC1 boot begin ===` / `WiFi LED init` / `UART0 stays GPIO1/3` 全部打印。
     代价：计量暂缓、U7 可能 ENODEV 降级。日志确认后 `POST /api/config {"debug_log_tx":false}` 切回计量。
3. 供电二选一：**要么 TTL 的 3V3**，**要么** 排插自身 220V（经 5V→3.3V）；两者同时接会打架。

## 6. 首次上电 → 手机配网 → AI 接管

详见 [`02-手机配网.md`](02-手机配网.md) 与 [`03-AI内网控制.md`](03-AI内网控制.md)，摘要：

1. 上电后连不上已知 WiFi → 自动开热点 `DC1-Setup` / `dc1setup`。
2. 手机连该热点 → 弹窗（或浏览器开 `192.168.4.1`）→ 选家里 2.4G SSID + 密码 → 保存。
3. 设备重启入网，mDNS `dc1-plug.local`。
4. PC 上 `python tools/dc1ctl.py state` 应能读到 5 个开关 + 电压/电流/功率。

## 7. 验收清单

| # | 检查 | 命令/方法 | 通过标准 |
|---|---|---|---|
| 1 | 上线 | `ping dc1-plug.local` | 有回应 |
| 2 | API | `python tools/dc1ctl.py list` | 列出 switch0~3 + 计量实体 |
| 3 | 分路 | `dc1ctl.py on 1` | 插孔1 继电器"咔"一声，实测通电 |
| 4 | 互锁 | 关总开关后 `on 2` | 总开关自动先合，插孔2 通电 |
| 5 | 记忆 | 关总开关再开 | 原开着的分路自动恢复 |
| 6 | 按键 | 手按 KEY1~KEY3 / 总键 | 与软件状态同步，无卡死 |
| 7 | 计量 | 插 60W 灯泡，`dc1ctl.py meter --watch` | 功率≈60W，电压 220±10V |
| 8 | OTA | `esphome run dc1-ai.yaml` | 内网升级成功，继电器不误动 |
| 9 | 掉电 | 拔插头 10s 再上 | 状态恢复，无反复重启 |

## 8. 回滚

```bash
esptool.py --port COM5 write_flash 0x0 backup/dc1_original_1M.bin
```
（须重新进入下载模式；原厂固件已无法连云，仅作硬件验证用。）

## 9. 风险与对策

| 风险 | 概率 | 后果 | 对策 |
|---|---|---|---|
| 焊盘脱落 / 排线拽断 | 中 | 板子报废 | 用测试探针免焊；拔排线先松卡扣，宁拆排线不撬板 |
| 误接 5V 到 3.3V | 低 | 模组烧毁 | TTL 只用 3.3V 档，接线前万用表量 |
| U7 通信失败 | 中 | 无法控制 | I2C 降 20k→10k，缩短飞线，检查 4.7k 上拉 |
| CSE7766 读数乱 | 中 | 计量错 | 确认 4800/8E1、`logger baud_rate: 0`、UART0 swap |
| 上电继电器全吸合 | 低 | 意外通电 | `restore_mode: RESTORE_DEFAULT_OFF` + 首次上电不接负载 |
| OTA 中途断电 | 低 | 变砖需重刷 | 保留焊好的测试点，OTA 时不断电 |

## 10. 与"原厂 App / 第三方固件"路线对比

| 路线 | 配网 | 局域网控制 | 状态回读 | 维护性 | 结论 |
|---|---|---|---|---|---|
| 原厂固件 + 内网 DNS 劫持 | 原 App（已废） | 需伪造云 | 差 | 已死 | ✗ |
| zDC1（安卓 App + MQTT） | 安卓 App | MQTT | 好 | 闭源二进制 | 可用但绑 App |
| qlwz/esp_dc1 | Web 配置 | MQTT/Web | 好 | 活跃过、已归档 | 备选 |
| **本方案 ESPHome** | 手机强制门户 | API + Web + MQTT | 好 | YAML 全开源、OTA | **推荐** |
