# 03 · 让 AI 通过内网控制排插

## 0. 结论

三条链路都能关灯开电器，但定位不同：

| 通道 | 端口 | 读状态 | 写控制 | 适合 |
|---|---|---|---|---|
| **Native API**（推荐） | 6053 | ✅ 事件推送，毫秒级 | ✅ | AI/脚本/HA，`tools/dc1ctl.py` 走这条 |
| Web Server | 80 | 页面/有限 | ✅ HTTP | 手机浏览器、临时调试 |
| MQTT | 1883 | ✅ retain | ✅ | 已有 broker（如 iotp/EMQX），要跨网段或联动多设备 |

本仓库默认三通道全开，AI 侧统一用 **Native API**（`tools/dc1ctl.py`），
理由：状态是设备主动推的，不是"猜"；且不需要额外 broker 常驻。

## 1. 一次性准备

```bash
pip install aioesphomeapi
set DC1_HOST=dc1-plug.local          # Windows CMD
# export DC1_HOST=192.168.36.50     # bash，或直接写 IP
set DC1_KEY=<secrets.yaml 里的 api_encryption_key>
```

`api_encryption_key` 生成：`openssl rand -base64 32`（ESPHome 要求 32 字节 base64）。

## 2. 常用命令

```bash
python tools/dc1ctl.py list                # 看实体清单（确认开关 key）
python tools/dc1ctl.py state               # 全部开关 + 电压/电流/功率/电量
python tools/dc1ctl.py on 1                # 开插孔1（无脑先合总闸）
python tools/dc1ctl.py off 1
python tools/dc1ctl.py toggle 2
python tools/dc1ctl.py off total           # 关总开关（三路 + USB 全断）
python tools/dc1ctl.py on logo             # LOGO 灯
python tools/dc1ctl.py meter --watch       # 每秒刷新功率，Ctrl-C 退出
```

典型输出：

```
总开关       ON             (Switch)
插孔1        OFF            (Switch)
插孔2        ON             (Switch)
插孔3        OFF            (Switch)
LOGO 灯      ON             (Switch)
DC1 排插 电压  220.4 V        (Sensor)
DC1 排插 电流  0.271 A        (Sensor)
DC1 排插 功率  59.8 W         (Sensor)
```

## 3. AI 侧接入方式

### 3.1 直接调 CLI（最省事，任何 Agent 都能用）

把 `tools/dc1ctl.py` 当成一个"设备命令"，AI 只需执行 shell：

```
用户：把插孔1 关掉，顺便报下现在功率
AI ：python tools/dc1ctl.py off 1 && python tools/dc1ctl.py state
```

### 3.2 包成 MCP 工具（给支持 MCP 的客户端）

```python
# tools/dc1_mcp.py（示例，需 pip install mcp）
import asyncio, json, subprocess
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("dc1")

def run(*args):
    out = subprocess.run(["python", "tools/dc1ctl.py", *args],
                         capture_output=True, text=True, timeout=15)
    return out.stdout or out.stderr

@mcp.tool()
def dc1_set(plug: str, on: bool) -> str:
    """控制 DC1 排插。plug ∈ total/1/2/3/logo"""
    return run("on" if on else "off", plug)

@mcp.tool()
def dc1_state() -> str:
    """读取 DC1 全部开关与电压/电流/功率"""
    return run("state")

if __name__ == "__main__":
    mcp.run()
```

注册到 MCP 客户端后，AI 就有了 `dc1_set` / `dc1_state` 两个原子能力。

### 3.3 HTTP（给不会装 Python 的场景）

```bash
# 需要 secrets.yaml 里的 web_username/web_password（Basic Auth）
curl -u admin:****** -X POST http://dc1-plug.local/switch/dc1_plug_1/turn_off
curl -u admin:****** http://dc1-plug.local/            # 拿 HTML 页面
```
> ESPHome Web Server v2 的动作只接受 POST，且 GET 不再返回 JSON；做自动化**不要**靠它读状态，
> 读状态请用 API 或 MQTT。

### 3.4 MQTT（已有 broker 时）

`firmware/upstream/dc1_mqtt.yaml` 是现成模板，topic 形如：

```
mqtt/0/phicomm_dc1/<device>/switch/switch1/set     # 下发 ON/OFF
mqtt/0/phicomm_dc1/<device>/switch/switch1         # 状态
mqtt/0/phicomm_dc1/<device>/sensor/power           # 功率
```

可以让 iotp/EMQX 上的规则引擎把消息转给你的 AI 网关；代价是多一个常驻 broker。

## 4. 典型自动化（AI 能直接照做的判断逻辑）

```python
# 过载保护：插孔2 给充电器，功率超 1500W 立刻断电并告警
state = dc1ctl.state()
if state["插孔2"]["power"] > 1500:
    dc1ctl.off(2); notify("插孔2 过载已断开")

# 电饭煲：功率从 <10W 跳到 >400W 即认为开始煮饭，15 分钟后关
# 睡前：off total，并把 shadow 记忆交给固件（重开时自动恢复）
```

固件内已带**互锁**与**断电记忆**：
- 开任一分路 → 总闸未合则自动先合（等价官方 App 行为）；
- 关总闸 → 三路状态存入 `shadow1~3`，再开总闸自动恢复。

## 5. 排障

| 症状 | 排查 |
|---|---|
| `连接失败` / 超时 | `ping dc1-plug.local`；Windows 无 mDNS 就用 IP；确认 PC 与设备同网段（无 AP 隔离） |
| 提示 `Invalid encryption key` | `DC1_KEY` 不是 secrets 里那串，或设备 OTA 后 key 变了 |
| 能读不能写 | 实体名匹配失败：先 `list` 看真实名称，改 `tools/dc1ctl.py` 的 `PLUGS` |
| 开关点了没反应但状态变了 | U7 通信问题：I2C 降到 10kHz，检查排线是否插到底 |
| 功率一直 0 | CSE7766 未通：确认 `logger.baud_rate: 0`、UART0 已 swap 到 GPIO13 |
| 状态偶尔全 OFF | WiFi 重连导致模组重启：`wifi.reboot_timeout: 0s` + `power_save_mode: none` 必须保留 |

## 6. 安全边界

- API/Web 都在**局域网明文**（API 有 Noise 加密，Web 是 Basic Auth + HTTP）。
  不要在公网做端口映射；远程要么 VPN，要么 MQTT over TLS 到自建 broker。
- 任何"自动断电"逻辑都要留**人工兜底**：按键始终可用，别把总开关锁死在软件里。
- 继电器是机械触点，别用它做高频 PWM/频繁通断（寿命约 1e5 次），定时任务间隔 ≥1 分钟。
