# TC1 硬件与电路资料

> **重要前提**：斐讯从未公开 TC1 的原理图或 EDA 源文件。本目录所有"电路图"都是
> **实物反推**：拆机高清照 + 社区按 PCB 手绘的原理图 + 芯片 datasheet 典型电路。
> 与 DC1 不同的是，TC1 的**主控不是 ESP8266**，原厂固件无法用 MicroPython 方案覆盖，
> 这一点决定了本仓库对 TC1 采取"换脑"路线（见第 7 节）。

## 2. 整机拓扑（依据实物照 + 手绘图）

```
AC L ─┬─ 总机械开关 ─┬─ RELAY1 ── 插孔1 ┐
      │              ├─ RELAY2 ── 插孔2 │
      │              ├─ RELAY3 ── 插孔3 ├─ 6 个五孔，独立通断
      │              ├─ RELAY4 ── 插孔4 │
      │              ├─ RELAY5 ── 插孔5 │
      │              └─ RELAY6 ── 插孔6 ┘
      │
      └─ USB 降压板（3×USB-A + 1×QC3.0 快充）── 不受 MCU 控制，仅受总机械开关

火线串采样电阻 ── BL0937(U4) ── CF 脉冲 ── U3(EL1019 光耦) ── 主控 GPIO（仅功率）
                    └─ CF1/SEL ── U6/U7(EL1019) ── **出厂未贴装，电压电流不可用**

强电取电 ── 非隔离降压 ── 5V(继电器) ── LDO ── 3.3V(模组/计量)
```

## 3. 两个硬件版本（唯一差别 = 主控）

| | **A1** | **A2** |
|---|---|---|
| 主控 | 庆科 **EMW3031-P**（丝印 `EMW3031-P`） | 汉枫 **HF-LPT230**（丝印 `HF-LPT230 VER2.0`） |
| 内核 | Cortex-M4F @100 MHz，192 KB RAM，2 MB SPI Flash | Cortex-M4 @200 MHz，448 KB RAM，1/4 MB Flash |
| 运行环境 | **MiCO**（庆科 IoT OS） | 汉枫私有固件 + AT 指令 |
| 刷机口 | 4 个 SWD 焊盘：`VCC / SWDIO / SWCLK / GND` | 4 个 UART 测试点：`3.3V / TX / RX / GND` |
| 烧录器 | J-LINK（十几元那种即可） | 任意 USB-TTL |
| 烧录方式 | J-Flash / MDK 下载 | 230400 8N1，按住按键 + GND 碰 pin10 进 boot，Xmodem 发送 |
| 社区固件 | zTC1（MiCO，需 MiCO Cube 编译） | TC1A2（汉枫 SDK，Keil+GCC） |

判定：看包装盒底部印字（`13-*.png`）；无包装就拆开看模组丝印（`12-*.png`）。

> 网传还有 RTL8195AM / ESP8266 原厂版本，**未获实物佐证**。社区主流文档（zTC1）明确
> 只有 A1/A2 两种主控，"ESP8266 版 TC1 可直接 esptool 刷写"一类说法属于把
> **换模块改造**误当成原厂配置，别照做。

## 4. A2 引脚表（HF-LPT230，模块侧 16 脚）

来源：汉枫《HF-LPX30 系列用户手册》表 3 + 社区实测功能列。

| 脚 | 名称 | 信号类型 | GPIO | 板上功能 |
|:--:|---|---|:--:|---|
| 1 | SPI_MOSI | IPD/O | GPIO12 | 计量 SEL（未贴装支路） |
| 2 | SPI_CLK | IPD/O | GPIO4 | 计量 CF1（未贴装支路） |
| 3 | SPI_MISO | IPD/O | GPIO7 | **BL0937 CF = 功率脉冲** |
| 4 | SPI_CS | IPD/O | GPIO5 | **面板 LED** |
| 5 | UART0_TX | O,PU | GPIO2 | TX 测试点 |
| 6 | UART0_RX | I | GPIO1 | RX 测试点 |
| 7 | UART0_CTS | IPU/O | GPIO22 | **RELAY1** |
| 8 | UART0_RTS | IPU/O | GPIO23 | **RELAY4** |
| 9 | ADC | IPD/O | GPADC0 | **RELAY5**（当数字口用） |
| 10 | EXT_RESETn | I,PU | — | 模组复位（刷机时 GND 碰它进 boot） |
| 11 | nReady | IPU/O | GPIO24 | **RELAY2** |
| 12 | nReload | IPU/O | GPIO25 | **按键 KEY**（长按恢复出厂/配网） |
| 13 | nLink | IPD/O | GPIO8 | **RELAY3** |
| 14 | GPIO3 | IPU/O | GPIO3 | **RELAY6**（上电会有 2 ms 低电平） |
| 15 | +3.3V | Power | — | 3.3V 测试点 |
| 16 | GND | Power | — | GND 测试点 |

**注意两处坑**：

1. 脚 9（ADC/GPADC0）和脚 14（GPIO3）不是普通 GPIO：脚 14 上电会输出 2 ms 低脉冲，
   继电器若不是"低电平不吸合"的接法，上电瞬间会有一路误吸合。
2. 手绘图 `09-*.png` 的 net 名（`PWM IO` / `LED` / `GPIO3`）与管脚表的 GPIO 编号命名
   不一致；**引脚归属以汉枫手册 + 管脚表为准**，手绘图只用来看拓扑与元件值。

## 5. 计量电路：只有功率，没有电压电流

- 芯片：**BL0937**（U4，SOP-8），火线串 1 mΩ 级采样电阻，CF 输出有功功率脉冲。
- 隔离：CF / CF1 / SEL 三路各经一只 **EL1019** 光耦（U3 / U6 / U7）进主控——
  强电侧与 MCU 侧完全电气隔离，这是 TC1 比 DC1（CSE7766 直连 UART）更稳的地方。
- **出厂只贴了 CF 通道**：`10-*.png` 里 U6/U7 输出侧的红框是未贴装元件。
  所以原厂固件与 zTC1 都**只能显示实时功率**，没有 V/A；想要 V/A 必须补焊元件
  （TC1A2 作者在 README 里也写了"需要把红框缺的元件补上去"）。
- 功率换算：`P(W) = 1000 × f_CF(Hz) / K`，`K` 为脉冲常数（imp/kWh），
  出厂典型 1600，**必须用外部功率计单点标定**（本仓库固件提供 `/api/cal`）。

## 6. 按键 / LED

```
按键 S7 一路：nReload(GPIO25) ── 短按：总开关；长按 3 s：进配网
LED：SPI_CS(GPIO5) ── R133 1K ── LED ── +5V     （低电平点亮）
Q5(S8050) + D4/D32 构成按键指示灯支路，按下时点亮
```

## 7. 两条刷机路线（本仓库选第 2 条）

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| ① 保原厂主控 | A1 用 zTC1（MiCO Cube 编译，J-LINK 烧）；A2 用 TC1A2（汉枫 SDK，UART 烧） | 不改硬件，完整 6 路 + 功率 | 工具链冷门（MiCO / Keil+汉枫 SDK），无法复用本仓库 MicroPython 体系 |
| ② **换脑（本仓库采用）** | 拆掉原模组，焊 ESP-12S/ESP-12F 转接板，跑 MicroPython，与 DC1 同一套协议 | 工具链与 DC1 完全一致（esptool + mpy-cross + `cli/dc1ctl.py` + Qt 上位机） | 需动烙铁（热风枪拆模组，400 ℃），失去原厂保修 |

路线 ② 的接线定义、烧录步骤、协议差异见 `docs/08-TC1方案.md`；固件在 `firmware/tc1/`。

## 8. 安全

- 6 路继电器触点直接挂在 220 V 上，插孔一体铜条与继电器间距很小；
  拆机后通电测试**先贴绝缘胶带盖住 AC 铜条**。
- 换脑时 USB 降压板与 AC 侧共板，热风枪吹模组前**先拆下电源板与绝缘片**，否则塑料会化。
- 刷机阶段只用 J-LINK / USB-TTL 的 3.3V 供电，**不要插 220 V**。
